# 部屋プランナー

自分の部屋を実寸で置き、家具の配置を検討するための個人用ツールです。内装を一般向けに提案するサービスではありません。画面の長さはセンチメートル、保存する長さはメートルです。2D と 3D は同じ配置を編集します。

公開 URL は https://sugarsgith.github.io/room-planner/ です。

## 使い方

ブラウザだけで動きます。配置はブラウザの localStorage に保存されます。

- **2D / 3D** … 上のボタンで切り替えます。2D はホイールで拡大、空白のドラッグで移動、家具のドラッグで移動です。緑の丸をドラッグすると 90° 単位で回転し、クリックすると右へ 90° 回ります。
- **数値** … 寸法も位置も底の高さもセンチメートルです（0.1 cm 単位）。位置は家具の中心。Enter か入力欄の外で確定し、その操作は元に戻す 1 回分になります。底の高さの初期値は 0 で、収納の上に置くときに使います。
- **保存** … 変更は約 400 ms 待ってから自動で保存されます。待っているあいだは「未保存の変更あり」、成功すると「保存済み 8:23」のように現地時刻が出ます。上の「保存」ですぐ書けます。書き込みに失敗すると「保存できませんでした」と出て、その後の自動保存は止まります。
- **矢印キー** … 選択中の家具を 1 cm 動かします。Shift で 10 cm。押し続けても履歴は 1 回です。
- **重なり** … 回転を考慮した足跡が重なる、部屋の矩形からはみ出す、天井や梁を超える、出っ張りや扉の開きとぶつかる、のいずれかで赤く警告します。接触だけ（すき間 0）は警告しません。底の高さが収納の天板以上なら、その収納の上には置けます。
- **部屋の出っ張り** … 柱、備え付け収納、天井の梁、窓、入口を足します。外形そのものは変えません。入力はセンチメートルで、実寸の初期値は入れません（入口の高さと手前の空きだけ、天井高と 60 cm から始められます）。追加したあとも行をクリックすれば直せます。壁の始点は、下=左端、右=手前、上=右端、左=奥です。窓の外側の出幅に、底の高さが窓台以上のものを置けます。入口の前に家具があると「入口をふさいでいます」。窓の前に家具があっても重なりにはしません。高いものが窓にかかると「窓にかかっています」と出ます。
- **重なってもいい家具** … 選択中の家具で、重ねてよい相手を選べます。どちらかが相手を選んでいれば警告しません。許可した側は 2D で薄く、破線で、相手より手前に描きます。
- **壁** … 3D の「壁を表示」「壁を半透明」。初期状態は半透明です。壁の厚みは室内寸法の外側にあります。
- **元に戻す** … ボタン、または Ctrl/⌘+Z。やり直すは Ctrl/⌘+Shift+Z と Ctrl+Y。
- **配置** … 左の「配置」で案を切り替えます。基準は編集できます。「複製」で検討案を足し、「比較」で基準と左右（電話では上下）に並べます。比較中は動かせません。「この案を編集」で戻ります。名前・色・寸法・形状は全部の案に共通です。底の高さと重なりの許可は、その案だけです。「この案から外す」とその案だけから消えます。「家具を消す」は確認のあと、入っている案すべてから消します。その家具の収納スペースと収納物も消えます。
- **収納** … 上の「収納」で、スペースのある家具と備え付け収納を一覧します。スペースの内寸、収納物の名前と数量、だいたいの大きさ（cm、空欄可）を直せます。空欄は「サイズ未入力」で、入るかの判定はしません。大きさがあるときは、横に回した場合だけ見て「入る / 高さが足りない / 向きを変えると入る / 入らない」と出します。個数ぶんの体積がスペースを超えるときは、その旨を足します。埋まり具合は体積の「目安」です。収納物に内寸を付けると入れ物になります。中の物はその内寸で判定し、入れ物の埋まり具合も出ます。入れ物は1個だけです。入れ物の中に、さらに入れ物は置けません。入れ物を外すときは、中の物をスペースに出すか、中まで消すかを選びます。検索は「冬服 / FITS（ベッド下）」のように場所を出します。配置画面では、選択中の家具にスペースと収納物を追加できます。移動しても、案から外しても残ります。備え付け収納は一覧に出ますが、中の記録はまだできません。正面の図はありません。
- **書き出し / 読み込み** … JSON ファイルです。読み込む前に「この端末の記録を、ファイルの内容に置き換えます」と確認します。キャンセルすると今の記録は変わりません。不正なファイルは読み込まず、今の配置もディスク上の保存も変えません。まだ書き出していないとき、または最後の書き出しから30日を過ぎたときは、画面上に案内が出ます。「あとで」で7日隠します。この案内は部屋のデータとは別の場所に記録します。

平面図の下辺が手前（Z = 0）、上辺が奥です。右が +X です。

初期の部屋は幅 270 cm、奥行き 360 cm、天井 240 cm（約 6 畳）です。シングルベッド、デスク、2人掛けソファ、丸テーブルが入っています。柱や窓は初期データには入っていません。

PC と iPad（幅 768 px 以上）は、家具一覧・平面図・部屋の 3 列です。それより狭い画面と、高さが 500 px 以下の横画面では、平面図を上に置き、その下の「家具」「編集」「部屋」で 1 枚だけ出します。上の「配置 / 収納」で画面を切り替えます。収納のとき、広い画面は一覧・中身・修正の 3 列、狭い画面は一覧か中身を縦に出します。「家具」「編集」「部屋」は配置のときだけです。

### ホーム画面に追加する

iPhone と iPad では Safari でこのページを開き、共有ボタンから「ホーム画面に追加」を選びます。名前は「部屋プランナー」です。追加したアイコンから開くと、ブラウザの枠なし（スタンドアロン）で使えます。そのときだけ、画面は時計の下から始まり、下のホームインジケータと、横向きのときの左右のノッチにも重なりません。Safari のタブで開いているときは、これまでどおりブラウザの枠の中です。

PC の Chrome や Edge では、アドレスバーのインストールから同じように追加できます。

iOS では、Safari のタブとホーム画面のアプリで保存領域が別です。同じ部屋のデータは自動では共有されません。書き出した JSON を、使いたい側で読み込んでください。

### 更新とオフライン

配置の自動保存とは別に、アプリ自体の新しい版が配信されると「新しい版があります」と出ます。編集中に勝手に読み込み直すことはありません。「更新」を押したときだけ、新しいサービスワーカーに切り替えてページを読み込み直します。配置データ（localStorage）には触れません。アプリの画面キャッシュは `room-planner-v2` です。アプリを前面に戻したときにも、新しい版がないか確認します。回線がないときは、直前に開いた版の画面を表示します。古いキャッシュは、新しい版が有効になったときに捨てます。

### 保存データが壊れていたとき

読み込みに失敗しても、保存済みの文字列は上書きしません。初期レイアウトを画面に出すだけで、自動保存は止まります。

- **生データを書き出す** … 壊れた文字列をそのままダウンロードします（バックアップキー `room-planner.project.v1.backup` にも写します）。
- **この内容で保存を再開** … 生データを書き出したあとだけ押せます。今画面にある内容で保存を上書きします。書き出す前は押せません。

## 開発

Node.js 22 です。パッケージマネージャは npm です。外部の有料 API は使いません。ESLint などの別リンターは入っていません。型チェックは `tsc --noEmit` で、`npm run build` の先頭で走ります。

```bash
npm ci          # ロックファイルどおりに入れる
npm run dev     # http://localhost:5173
npm test        # Vitest
npm run build   # 型チェックと本番ビルド
npm run preview # dist を配信
npm run e2e     # 先に build。Playwright の Chromium が必要
```

Chromium が無いときは `npx playwright install chromium` です。

## 公開

`vite` の `base` は `./` です。サブパス（GitHub Pages）でも、ドメイン直下でも同じ `dist` を置けます。

GitHub Pages 用のワークフローは `.github/workflows/pages.yml` です。`main` への push で `npm ci`、`npm test`、`npm run build`、続いて `actions/deploy-pages` が動きます。プルリクエストだけではこのワークフローは走りません。

**初回だけ、リポジトリの Settings → Pages → Build and deployment → Source を GitHub Actions にしてください。** この設定はワークフローファイルだけでは有効になりません。

Cloudflare Pages では、ビルドコマンド `npm run build`、出力ディレクトリ `dist`、Node 22 を指定します。環境変数やトークンは不要です。

## データ形式

localStorage のキーは `room-planner.project.v1` です。名前の v1 は保存枠で、中身の `schemaVersion` とは別です。書き出す JSON も同じ形です。長さはメートルです。画面だけセンチメートルで、0.1 cm 格子です。

| キー | 役割 |
| --- | --- |
| `room-planner.project.v1` | いまの文書 |
| `room-planner.project.v1.backup` | 読めなかった文字列のコピー。元キーは上書きしない |
| `room-planner.project.v3.backup` | v4 へ移す直前の文字列。一度だけ書き、既にあれば上書きしない |
| `room-planner.project.v4.backup` | v5 へ移す直前の文字列。v3 の退避は上書きしない |
| `room-planner.export-reminder.v1` | 書き出し案内の日時。部屋の文書ではない |

退避に失敗したときは v4 を書きません。壊れた JSON は移行せず、元の文字列も上書きしません。

いまの `schemaVersion` は `5` です。`1` から `4` は読み込み時に 5 へ移行します。それ以外の版は拒否します。v3 形式へ書き戻すボタンはありません。

- **1** … 家具が各レイアウトの `furniture` に入った初期形。`fixtures` と `elevation` と `allowOverlapIds` は無いことがあります。
- **2** … `room.fixtures`（柱・備え付け収納・梁）が加わる。
- **3** … 窓・入口・底の高さ・重なり許可が加わる。家具はまだレイアウトの中に寸法ごと入っています。
- **4** … 家具の名前・形状・寸法・色は `furniture` に 1 回。各案は `placements`（位置・回転・底の高さ・重なり許可）だけです。`baselineLayoutId` が基準です。同じ id で寸法が食い違うときはカタログを分裂させ、`originId` を残します。
- **5** … 家具カタログに `spaces`（名称・内寸・メモ）、文書に `storedItems`（名前・数量・保管場所・メモ）が加わります。配置には入れません。収納物の外形 `width` / `depth` / `height`、入れ物の内寸 `innerWidth` / `innerDepth` / `innerHeight`、中に入っているときの `containerId` は、すべて任意です。`spaceId` は家具のスペースのままです。公開中の版 5 はこれらの項目を知らないので、入れ物の中の物も、そのスペースの普通の収納物として表示します。家具の移動など、いつもの保存では項目を落とさず残します。版は 5 のままです。備え付け収納の中の台帳はまだありません。

```json
{
  "schemaVersion": 5,
  "app": "room-planner",
  "room": {
    "id": "room-main",
    "name": "自分の部屋",
    "width": 2.7,
    "depth": 3.6,
    "ceilingHeight": 2.4,
    "outline": [
      { "x": 0, "z": 0 },
      { "x": 2.7, "z": 0 },
      { "x": 2.7, "z": 3.6 },
      { "x": 0, "z": 3.6 }
    ],
    "openings": [],
    "fixtures": []
  },
  "furniture": [],
  "storedItems": [],
  "layouts": [
    {
      "id": "layout-default",
      "name": "現在の配置",
      "placements": []
    }
  ],
  "activeLayoutId": "layout-default",
  "baselineLayoutId": "layout-default"
}
```

原点は床の手前左です。+X は右（幅）、+Y は上、+Z は奥（平面図では上）です。家具の `x` / `z` は足跡の中心、`rotation` は上から見て時計回りの度です。0 のとき幅は +X、奥行きは +Z です。

`room.fixtures` は柱（`pillar`）、備え付け収納（`storage`）、天井の梁（`beam`）、窓（`window`）、入口（`entrance`）です。角は `back-left`（左上）など、壁は `back`（上）・`right`・`front`（下）・`left` です。壁に沿った距離の起点は、下=左端、右=手前、上=右端、左=奥です。寸法はメートルです。

読み込み時は版・必須項目・数値（正の有限数、許容範囲）・未知の形状を検査します。失敗した内容は適用しません。多角形の部屋、古い `openings`、複数レイアウトをファイルに含めることはできますが、編集 UI は長方形の一部屋とアクティブな配置だけです。幅または奥行きを画面から変えると、外形は原点基準の長方形に戻ります。詳細は `AGENTS.md` と `docs/future-extensions.md` を見てください。

## 既知の問題と未実装

- 入口から奥までの通れる一本の幅は未実装です。比較に出るのは、歩行面の家具と壁・柱・備え付け収納との最小すき間です。
- 3D を 2 案並べる表示はありません。比較は 2D だけです。
- v4 から v3 への書き出しはありません。古いアプリは schema 4 を拒否し、そのとき元キーは上書きしません。
- iOS では Safari とホーム画面アプリの localStorage が別です。
- 収納の台帳は家具のスペースだけです。備え付け収納は一覧に出ますが、中はまだ記録できません。上面図、正面図、中の 3D はありません。
- 部屋の外形を凹ませる編集、GLB、画像書き出し、廊下は未実装です。
- はみ出し判定は外接矩形に対してだけです。
